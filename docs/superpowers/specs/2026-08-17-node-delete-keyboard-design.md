# Node 外壳 Delete 快捷键设计

## 背景

`FlowCanvas` 已经支持单选、框选/多选，以及通过节点右键菜单删除节点。删除节点时，现有 `RemoveNode` 会同步移除相关连线并清理相邻输入端口的 `LinkId`。当前缺少键盘入口，用户无法在选中节点后直接按 `Delete` 删除。

节点内容由插件提供，可能包含 `TextBox`、下拉框、按钮、滑块等可交互控件。快捷键不能在这些控件获得焦点时抢占 `Delete`，否则会破坏文本编辑或控件自身的行为。

## 目标

1. 选中的节点外壳获得键盘焦点后，按 `Delete` 删除节点。
2. 单选时删除当前节点，多选时删除全部选中节点。
3. 删除复用现有节点删除和连线清理逻辑。
4. 节点内部的编辑控件或其他元素获得焦点时，按 `Delete` 不删除节点。
5. 没有节点外壳焦点时，按 `Delete` 不产生节点删除行为。

## 非目标

- 不新增撤销/重做系统。
- 不改变右键菜单删除行为。
- 不把 `Backspace` 或其他按键映射为删除。
- 不改变节点内部控件已有的键盘行为。
- 不要求框选结束后自动把焦点转移到某个节点外壳；若框选后焦点不是节点外壳，`Delete` 按键按设计不删除。

## 方案选择

### 方案 A：窗口级快捷键

在窗口或页面级监听 `Delete`，再根据当前选中状态删除节点。

优点是实现入口集中；缺点是必须手动排除节点内部控件和其他输入场景，容易误删，且快捷键作用域过大。

### 方案 B：FlowCanvas 统一监听并判断焦点

在画布事件路由上监听 `PreviewKeyDown`，检查当前焦点是否位于选中节点外壳。

优点是实现范围小；缺点是外壳焦点语义需要额外判断，未来新增内容控件时容易漏掉排除条件。

### 方案 C：NodeView 外壳焦点 + 画布删除处理（采用）

让 `NodeView` 本身代表节点外壳并可获得焦点，点击非交互区域时由画布选中节点并将焦点转移到 `NodeView`。画布只在当前键盘焦点正是已选中的 `NodeView` 时处理 `Delete`。

该方案将“可以删除”的条件直接绑定到 WPF 焦点对象：节点外壳可删除，内部 `TextBox`、`ComboBox`、按钮、滑块等控件不会满足条件，行为边界清晰。

## 详细设计

### 1. 外壳焦点

- `NodeView` 设置为 `Focusable = true`。
- `NodeView` 设置为 `IsTabStop = false`，避免节点进入 Tab 导航顺序。
- 节点由画布创建时应用上述焦点属性。
- 点击节点非交互区域时，画布在设置选中状态后调用 `Focus()`，使 `NodeView` 成为键盘焦点对象。
- 点击节点内部交互控件时，不调用 `Focus()`；WPF 保持控件自己的焦点。

“外壳焦点”具体定义为：`Keyboard.FocusedElement` 直接是某个 `NodeView`，而不是它的任何后代控件。

### 2. Delete 事件范围

- 在 `FlowCanvas` 模板的视口事件路由上监听 `PreviewKeyDown`，确保节点外壳获得焦点时事件能到达画布。
- 仅响应 `Key.Delete`。
- 处理前检查当前焦点是否是 `NodeView`，且该节点仍在 `_selectedNodes` 中。
- 当前焦点不满足条件时直接返回，不设置 `Handled`，不删除任何节点。
- 满足条件时设置 `Handled = true`，避免同一次按键继续触发其他删除处理。

### 3. 删除行为

抽取一个供右键菜单和键盘入口共用的删除选中节点方法：

- 以当前 `_selectedNodes` 的节点 ID 快照为删除集合。
- 若焦点节点是唯一选中节点，删除该节点。
- 若焦点节点属于多选集合，删除全部选中节点。
- 每个节点通过已有 `RemoveNode` 删除，复用模型、视图、连线和端口引用清理。
- 删除完成后清空 `_selectedNodes`、清空 `SelectedNode` 并刷新选中视觉状态。
- 删除后保留画布焦点/无节点焦点状态，不自动把焦点转移到插件内部控件。

### 4. 生命周期与模板

- `OnApplyTemplate` 订阅视口的 `PreviewKeyDown`。
- `DetachViewportHandlers` 取消订阅，避免模板重应用后重复处理。
- 现有鼠标、拖拽、框选和右键菜单逻辑保持不变。

## 测试设计

在现有 WPF 自运行测试中补充 `FlowCanvas` 场景测试，使用已存在的模板化画布测试辅助方法。

### 必测行为

1. 节点外壳获得焦点且节点已选中时，`Delete` 删除节点，并清理关联连线。
2. 多个节点被选中且其中获得焦点的节点属于选中集合时，`Delete` 删除全部选中节点。
3. 节点内部 `TextBox` 获得焦点时，`Delete` 不删除节点，事件不被节点删除逻辑消费。
4. 焦点在画布、窗口或其他非节点元素时，`Delete` 不删除节点。
5. 非 `Delete` 按键不触发删除。
6. 模板重新应用后，键盘事件不会重复执行。

### 验证方式

- 先加入至少一个会因功能缺失而失败的测试，并确认失败原因是没有键盘删除行为。
- 完成最小实现后运行新增测试和现有 `NodeCraft.Tests`。
- 运行 `dotnet build NodeCraft.sln --no-restore --verbosity minimal`。
- 检查工作区 diff，确认只包含本功能相关变更。

## 风险与处理

- 插件内容可能自定义焦点行为：删除逻辑只接受 `NodeView` 作为直接焦点对象，因此不会误删。
- 节点选中但焦点仍在画布时，快捷键不会删除：这是“只有外壳获得焦点才删除”的明确约束。
- 右键菜单删除和键盘删除若分别维护多选清理，可能产生行为差异：通过共享删除选中方法避免重复逻辑。
